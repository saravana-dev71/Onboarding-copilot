## 4. Key Drift Findings

### 🔴 High-impact drifts

**D-1 — `AGENTS.md` footgun: FastMCP line number is wrong**  
> "server.py line 22 instantiates `FastMCP` before `FastAPI`"

The current code creates `app = FastAPI(...)` at **line 44** and `mcp = FastApiMCP(app)` at **line 336**. FastAPI is instantiated **first**, not FastMCP. The order note is inverted, and the line number is incorrect by ~300 lines. Any agent relying on this comment to understand server.py startup order will be misled.

**D-2 — Java hold-service README: wrong default port for Python backend**  
> "Prerequisites: Python backend running on port 8000"  
> "`PYTHON_BACKEND_URL` default: `http://localhost:8000`"

The actual default in [`application.properties:16`](../../booking_system_inventory_hold_service/src/main/resources/application.properties:16) is `http://localhost:8001`. A developer starting only the hold service using the README instructions will configure the wrong URL and get connection failures.

**D-3 — `AGENTS.md` footgun: conftest patching description is incorrect**  
> "Tests must patch `SessionLocal` in two places — conftest.py lines 49–50 patches both `db.SessionLocal` and `server.SessionLocal`"

The actual mechanism is `dependency_overrides[get_db]` — FastAPI's DI override — not direct attribute patching of `SessionLocal`. This misrepresents the test isolation strategy and will confuse a developer debugging test DB issues.

### 🟡 Medium-impact drifts

**D-4 — `AGENTS.md` footgun: `SEED_DEMO_DATA=true` does NOT re-seed every start**  
> "set to `false` if you need data to survive a restart locally"

[`seed.py:17-20`](../../booking_system_backend/seed.py:17) checks `if db.query(User).count() == 0` before seeding. Data already present is never overwritten, regardless of `SEED_DEMO_DATA`. The documented footgun implies a destructive re-seed that doesn't happen.

**D-5 — `AGENTS.md`: `DATABASE_URL` default expressed as bare path**  
> "DATABASE_URL is intentionally unset on ECS; db.py defaults to `./booking.db`"

The actual default is the SQLAlchemy URI `sqlite:///./booking.db`. While functionally understood by developers, it is misleading when setting the env var directly.

**D-6 — Backend README: "One codebase, one port (8080), both protocols"**  
Native `python server.py` binds to port **8001**; the Docker container exposes **8080**. Two distinct ports exist depending on execution context.

**D-7 — Java hold-service README: Spring Boot version `3.2.0`**  
The actual version in [`pom.xml:19`](../../booking_system_inventory_hold_service/pom.xml:19) is **3.4.1**.

### 🟢 Low-impact drifts

**D-8 — `holds.db` and `booking.db` described as committed artefacts**  
Neither file was present in the repository at audit time. They may be .gitignored or generated at first run.

**D-9 — `docs/onboarding/architecture.md`: localStorage key is `galaxium_holds_`, not `holds_`**  
Minor string difference in [`holdStorage.ts:3`](../../booking_system_frontend/src/utils/holdStorage.ts:3).

**D-10 — Java hold-service README: Java 17 or 21 required**  
`pom.xml` only explicitly targets **Java 17** (`maven.compiler.source=17`). Java 21 compatibility is not tested or declared in the build config; the claim is technically unverifiable from the build config alone.

**D-11 — `AGENTS.md`: MCP tools said to bypass FastAPI DI**  
The current codebase uses `FastApiMCP(app)` which auto-generates MCP tools from existing REST routes. No standalone MCP tool functions with direct `SessionLocal()` calls were found. The described implementation may describe an older architecture.
